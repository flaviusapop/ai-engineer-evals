Efficiency and performance

Interactive latency

Covers voice stage readiness and overlap, not aggregate inference throughput.

Download Markdown

On this page

  • Measure audible response and downstream readiness
  • Overlap voice processing provisionally

A voice user does not experience a first token or a network byte. The relevant conversational gap starts at the caller’s last syllable and ends when meaningful agent speech becomes audible. Measuring that interval per utterance, alongside the boundaries of the intervening stages, reveals delays that a fast component metric can conceal. [1] [2]

Measure audible response and downstream readiness

Instrument the caller’s last syllable, the turn-completion decision, recognition and model readiness, the first text the speech stage can use, the first synthesized byte and the first meaningful sound heard by the caller. Record function calls and handoffs where they lie on the response path. The end-to-end gap answers the experience question; the intermediate markers help locate the delay. Overlapping stages need their actual timestamps: adding all component durations as if they were serial can misstate the critical path. [1] [3]

A TTS service can send bytes that contain initial silence. One speaker reports observing up to 750 milliseconds of silence after an early response byte, but does not name providers or give sample counts, distributions or the silence-detection method. That report motivates measuring audible onset; it does not establish a typical delay or a ranking of providers. [2] [4]

Likewise, the first language-model token is useful only if the next stage can consume it. In the described pipeline, speech synthesis waits for a complete sentence, so time to first sentence can matter more than time to first token. A different streaming synthesizer may accept a smaller unit: measure the actual readiness boundary for the deployed pipeline rather than imposing the sentence assumption everywhere. A model that wins on token onset can lose on time to usable speech. [5] [6]

The speakers suggest 500–600 milliseconds as a more human-like target and around 1.5 seconds as a tolerable upper region. These are practical heuristics, not controlled perception thresholds or universal accessibility requirements; related presentations should not be counted as independent confirmation. Choose a budget appropriate to the interaction, then preserve useful and reliable behavior inside it rather than selecting the fastest component regardless of its effect on the task. [1] [7]

These per-utterance timestamps answer a different question from an aggregate serving SLO, and neither is the same as a GPU kernel microbenchmark. A fast kernel does not guarantee a quick spoken response if turn detection, sentence buffering or synthesis dominates. Conversely, an average voice gap alone does not guarantee acceptable tail behavior. For serving measurement and SLOs, see Measuring inference serving performance; for isolated hardware performance verification, see Verifying performance and kernel changes.

Overlap voice processing provisionally

A turn detector can decide that speech has ended while automatic speech recognition is still finalizing its text. Instead of waiting serially, start model work on a provisional transcript and compare it with the final transcript. If the words agree, the work already done may move the response closer to the caller. The speaker reports a possible half-second saving in this matching case; it is not a measured guarantee for other workloads. Synthesis can begin once this pipeline has the speakable unit it requires. [3]

The mismatch case determines whether the optimization is safe. If final recognition changes a date, amount or intent, provisional output may be wrong. A design needs a policy for discarding or revising speculative work, cancelling stale output and preventing premature tool side effects; the presentation does not specify those mechanisms. Until such handling is established, treat early work as provisional rather than as authority to execute an irreversible action. Measure both the matching-case benefit and the cost and consequences of corrections. [3]

This is overlap between voice pipeline stages, not the token-level target-verified mechanism described in Speculative decoding. Slow external operations create a separate conversational design problem; see Voice-agent operations.
